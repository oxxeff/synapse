# 0.1.0 - 2026-06-01

First release of Synapse: a thin, declarative webhook router from Gitea to
Jenkins. It reads a repository's `.synapse.yaml`, decides what to run and for
whom, triggers the executor and reports back to the pull request. It carries no
business logic of its own.

## Intake

- HMAC-SHA256 verification of inbound Gitea deliveries, in constant time.
- Retry deduplication via an in-memory delivery window with a TTL.
- Payload parsing into a normalized, executor-neutral event (comment, label, merge).

## Contract

- `.synapse.yaml` v1: commands with triggers (`on_comment`, `on_label`,
  `on_merge`), `available_in` states, ACL fields, a job and parameters.
- Strict schema validation; an unsupported version or any violation is rejected
  with a comment in the pull request.
- The contract is read from the repository default branch, so a change to it
  takes effect only after review and merge.

## Access control

- Initiator authorization through the Gitea API: `min_permission`,
  `allowed_users`, `allowed_teams`, unioned by OR, defaulting to write. API
  errors fail closed.

## Execution and reporting

- Parameter assembly from inline arguments, the PR description block and declared
  defaults, with `{{ ... }}` templating and a `SYNAPSE_` pull request context.
- Executor-neutral trigger/status interface with a Jenkins implementation: CSRF
  crumb, `buildWithParameters`, queue-to-build correlation and status polling.
- Synchronous-with-timeout report model: a bounded background pool waits for the
  build and posts a summary comment, handing off to the executor on timeout.
- Loop protection: events from the service's own bot account are ignored.
