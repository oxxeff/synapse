# 0.2.0 - 2026-06-01

Second release: event routing beyond pull request comments. Synapse now reacts to
tag creation and to a freshly opened pull request, while the v1 contract stays
backward compatible.

## Added

- `on_tag` trigger: route Gitea tag-creation events (the `create` delivery with
  `ref_type=tag`) to executor jobs by a glob on the tag name, for example `v*`. A
  tag has no pull request, so authorization is checked against the tag pusher,
  `available_in` does not apply, and parameter templates use `tag.name` and
  `tag.commit` (with `SYNAPSE_TAG`/`SYNAPSE_TAG_COMMIT` in the service context).
  The common case: a release tag is delivered to the mirror, where CI publishes
  the release.
- Opt-in `annotate_pr`: when a pull request is opened, Synapse appends a synapse
  parameter-block template to its description, listing each command's configurable
  params with their defaults, so the author fills values instead of recalling the
  format. It is idempotent (a description that already has a block is left
  untouched), posts nothing when no command exposes a param, and is off by
  default. The bot's own edit returns as an unsupported event, so it cannot loop.

## Compatibility

- Backward compatible. Both additions are opt-in (`annotate_pr`) or event-scoped
  (`on_tag`); the `.synapse.yaml` contract version stays `1` and existing
  contracts work unchanged. No manual migration.

## Notes

- `on_tag` requires the repository webhook to be subscribed to Create events. That
  is a Gitea-side setting, outside the contract.
